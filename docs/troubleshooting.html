Troubleshooting Guide

Find solutions to common issues and platform-specific problems with WiFi Jammer.

Common Issues

"No wireless interfaces found"

▼

Possible Causes:

  • Your wireless card doesn't support monitor mode
  • Wireless interface is not available or disabled
  • Driver issues with your wireless adapter

Solutions:

  1. Check available interfaces: 
    # Linux
iwconfig
ifconfig

# macOS
ifconfig
networksetup -listallhardwareports

# Windows
ipconfig /all
  2. Verify monitor mode support: 
    # Linux - check if your card supports monitor mode
iw phy | grep -A 10 "Supported interface modes"
  3. Enable wireless interface: 
    # Linux
sudo ifconfig wlan0 up

# macOS
sudo ifconfig en0 up
  4. Check driver compatibility: Some wireless adapters have limited or no monitor mode support. Research your specific adapter model.

"Permission denied" errors

▼

Possible Causes:

  • Not running with root/administrator privileges
  • Insufficient permissions for wireless interface access
  • macOS System Integrity Protection (SIP) restrictions

Solutions:

  1. Run with sudo (Linux/macOS): 
    sudo wifi-jammer attack --tui
sudo wifi-jammer --gui
  2. Run as Administrator (Windows): 
    # Right-click PowerShell/CMD and select "Run as Administrator"
wifi-jammer attack
  3. Check user permissions (Linux): 
    # Add user to netdev group (Debian/Ubuntu)
sudo usermod -aG netdev $USER
# Log out and back in for changes to take effect
  4. macOS Location Services: See the macOS-specific section below.

"Interface not found"

▼

Possible Causes:

  • Interface name is incorrect
  • Interface name differs between systems
  • Interface is disabled or not available

Solutions:

  1. List all interfaces: 
    # Linux
iwconfig
ip link show

# macOS
ifconfig | grep "^[a-z]"
networksetup -listallhardwareports

# Windows
ipconfig /all
  2. Common interface names:
    • Linux: wlan0, wlp2s0, wlan1
    • macOS: en0, en1 (usually en0 for WiFi)
    • Windows: Wi-Fi, Wireless Network Connection
  3. Use interface discovery: Let the tool automatically detect interfaces: 
    wifi-jammer scan  # Will show available interfaces

macOS: "SSID/BSSID are None" or networks show as "<redacted>"

▼

Cause:

macOS requires Location Services permission to access WiFi network information for privacy reasons.

Solutions:

Quick Fix: Run bash install.sh or bash quick_install.sh - they automatically run setup and request permission.

Manual Fix:

  1. Open System Settings (or System Preferences on older macOS)
  2. Go to Privacy & Security → Location Services
  3. Enable Location Services (toggle ON)
  4. Find "Python" or "python3" in the list
  5. Check the box ✅ to allow location access
  6. Restart the WiFi Jammer tool
Note: The tool automatically detects which Python has permission and uses it. You may need to grant permission to multiple Python installations if you have several.

Monitor mode problems

▼

Possible Causes:

  • Wireless card doesn't support monitor mode
  • Driver doesn't support monitor mode
  • Interface is already in use
  • macOS limitations with monitor mode

Solutions:

  1. Check monitor mode support (Linux): 
    iw phy | grep -A 10 "Supported interface modes"
  2. Put interface in monitor mode manually (Linux): 
    sudo ifconfig wlan0 down
sudo iwconfig wlan0 mode monitor
sudo ifconfig wlan0 up
  3. macOS: Monitor mode on macOS is limited. The tool uses alternative methods, but some features may not work as expected.
  4. Check if interface is in use: 
    # Linux
sudo lsof | grep wlan0
# Kill processes using the interface if necessary

Attacks not working / No packets sent

▼

Possible Causes:

  • Interface not in monitor mode
  • Wrong channel selected
  • Target BSSID incorrect
  • Firewall blocking packets
  • Driver issues

Solutions:

  1. Enable verbose mode: 
    sudo wifi-jammer --verbose attack --interface en0 --target 00:11:22:33:44:55 --attack deauth
  2. Verify target BSSID: Make sure the BSSID format is correct (XX:XX:XX:XX:XX:XX)
  3. Check channel: Ensure you're on the same channel as the target network
  4. Test with scan first: 
    sudo wifi-jammer scan --interface en0
  5. Check firewall: Temporarily disable firewall to test

Platform-Specific Troubleshooting

macOS

macOS Support: Enhanced support for macOS including M1/M2/M3 ARM chips.

Common macOS Issues:

  • Location Services: Required for network scanning. See above for fix.
  • Monitor Mode: Limited support on macOS. Some features may not work.
  • Python Permissions: Multiple Python installations may need separate permissions.
  • System Integrity Protection: May restrict some operations even with sudo.

macOS Setup Script:

Use the automated setup script for macOS:

bash tools/setup_macos.py
# or
bash install.sh

Linux

Common Linux Issues:

  • Driver Support: Some wireless drivers don't support monitor mode well
  • NetworkManager: May interfere with monitor mode. Try disabling it temporarily
  • Permissions: May need to add user to netdev group

Linux Setup Tips:

# Disable NetworkManager for the interface (temporarily)
sudo nmcli device set wlan0 managed no

# Put interface in monitor mode
sudo ifconfig wlan0 down
sudo iwconfig wlan0 mode monitor
sudo ifconfig wlan0 up

# Re-enable NetworkManager when done
sudo nmcli device set wlan0 managed yes

Windows

Windows Limitations: Windows has limited functionality due to driver and API restrictions. Some features may not work.

Windows Requirements:

  • Administrator privileges required
  • Compatible wireless adapter with monitor mode support
  • May require additional drivers (e.g., WinPcap, Npcap)

Debug Mode

Enable verbose output to see detailed information about what's happening:

sudo wifi-jammer --verbose attack --interface en0 --target 00:11:22:33:44:55 --attack deauth

Diagnostic Tools

Use the built-in diagnostic tool to check your environment:

# Check root access and Scapy installation
python3 tools/check_root.py

# Or with sudo to test root access
sudo python3 tools/check_root.py

The diagnostic tool checks:

  • Root/admin privileges (EUID on Unix, Admin on Windows)
  • Scapy installation and functionality
  • Network interface availability
  • macOS-specific: /dev/bpf* device access

Getting Help

If you're still experiencing issues:

1. Check Existing Issues

Search the GitHub issues page for similar problems:

View Issues on GitHub

2. Create a New Issue

When creating a new issue, please include:

  • Operating system and version
  • Python version (python3 --version)
  • Wireless interface name and type
  • Full error message
  • Steps to reproduce
  • Output from tools/check_root.py

3. Community Support

Join discussions and get help from the community:

  • GitHub Discussions
  • Check the Usage Guide for detailed instructions

Prevention Tips

To avoid common issues:

  • Always run with sudo (Linux/macOS) or as Administrator (Windows)
  • Grant Location Services permission on macOS before first use
  • Use the automated installation scripts when possible
  • Verify your wireless adapter supports monitor mode before use
  • Keep Python and dependencies up to date
  • Check interface names with ifconfig or iwconfig before specifying them
